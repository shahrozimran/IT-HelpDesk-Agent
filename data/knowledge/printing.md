# Printing and queue troubleshooting

SYNTHETIC TRAINING DOCUMENT. Version 2026-11-01. The Campus-Lab-Printer device is fictional. The assistant offers guidance and simulated tickets, not remote printer administration.

## Establish the printing symptom
Ask whether the printer is absent, appears offline, shows a paper or toner warning, or has a stalled job. Identify the operating system and the exact message. Check that the device is powered on and that the user is on the authorized network. If many people cannot print, check the simulated printing service status. Do not assume that a printer marked offline has a broken driver.

If the device displays an ordinary paper warning, ask the user to check the visible status panel and follow the device's posted instructions. Do not tell an untrained user to open restricted covers or repair internal electrical parts. A network-wide printing outage should lead to a service update or support escalation rather than repeated local reinstalls.

## Queue and connection checks
For Windows 11, open Settings, Bluetooth & devices, Printers & scanners and select the intended printer. Check that the correct device is selected for the application. Inspect the queue and determine whether only this user's job is stuck. Ask the user to cancel their own failed job and retry a small non-sensitive test document once. They should not remove another user's queued work.

If the printer is missing, use only installation details supplied by the authorized administrator. Do not invent an IP address, install unknown drivers or request administrator credentials in chat. If printing fails only from one application, test another permitted application to distinguish a document or application issue from a shared service failure. Record completed checks so a follow-up does not repeat them unnecessarily.

## Printing escalation
Escalate a persistent offline state, repeated queue failures or a multi-user incident after basic checks. Collect the printer's displayed name, operating system, error text, whether other users are affected and the result of the small test job. Do not attach private documents or print contents to a simulated incident.

A simulated ticket can be drafted in the printing category. Show its summary to the user before creation. The application requires separate confirmation and returns an actual stored ticket identifier through MCP. A draft ID beginning D- is not a ticket ID beginning HD-. No automated action in this project restarts the real print spooler or changes a live printer.
