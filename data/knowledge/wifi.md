# Campus Wi-Fi troubleshooting

SYNTHETIC TRAINING DOCUMENT. Version 2026-11-01. This fictional university's network is Campus-Lab. Nothing in this guide represents an official UCP configuration. The assistant must describe every service status as simulated and must not configure a real device automatically.

## Initial Wi-Fi checks
For a Windows 11 laptop that cannot connect, first establish whether the network is visible, whether other devices are affected, and the exact error message. Open Settings, Network & internet, Wi-Fi. Confirm Wi-Fi is enabled and airplane mode is off. Move within normal access-point coverage. Select Campus-Lab, not an unfamiliar hotspot. If other devices also fail, check current simulated Wi-Fi service status before spending time changing the laptop. A saved document cannot establish whether an outage is happening now.

If the service is operational, ask whether the device connects but has no internet, or cannot authenticate at all. Test another permitted website to distinguish a single-site problem from general connectivity. A working service status does not prove the user's laptop is correctly configured. Record steps the user already attempted; avoid repeating them without explaining why the conditions have changed.

## Device-specific recovery
If Campus-Lab is visible but connection fails and no outage is reported, ask the user to turn Wi-Fi off and on once. If that fails and they know how to sign in again, suggest forgetting only the Campus-Lab saved profile and reconnecting using their own account. Explain that forgetting a profile removes its saved connection information. The assistant must never ask the user to disclose the password. If the issue is an authentication rejection, consult the account-access guide instead of assuming that the network is down.

Avoid a full network reset, driver removal or administrator commands as initial advice. These may disrupt other connections and require an authorized technician. If the laptop connects to other authorized networks but not Campus-Lab, collect the operating system, error text, approximate location and whether another device can connect. These non-secret details help a technician reproduce the problem.

## Wi-Fi outage and escalation
If the current simulated service tool reports a Wi-Fi outage, suspend repeated profile deletion, router restarts and password changes. Explain that the evidence points to a shared service problem. Suggest waiting for the service update or using a permitted alternative connection, such as an existing approved wired connection. Do not promise a recovery time unless the current tool result explicitly supplies one.

Escalate if two basic checks fail with no known outage, or if several users in one area are affected. Prepare a simulated ticket only when requested or accepted by the user. Include symptoms, location, operating system, completed checks and the observed service status. Obtain separate user confirmation before creating the ticket.
